Concrete demonstration of non-determinism (item B1 from the critical review)
============================================================================

CONTEXT: the reviewer asked for the "ambiguous" finding to be promoted to a
co-primary result, with a real test: do several VCF readers
(bcftools, pysam, GATK) return the same identifier at the 63 ambiguous
sites of dbSNP144?

CONSTRAINT: a literal bcftools/pysam/GATK test requires the WSL
environment, currently down (Hyper-V/WSL outage documented earlier in
this session, awaiting a Windows restart).

TEST ACTUALLY RUN INSTEAD (honest about the substitution): the same bundle
file was parsed TWICE with a simple key-value collection (the kind of
code a quick annotation script would naturally write) -- once reading the
file in normal order, once in reverse order. The file's content
never changes, only the traversal order changes.

RESULT
--------
**63 ambiguous sites tested -> 63 disagreements (100%)** between normal order
and reversed order. Real examples:
  chr20:49,283,799 G>C: normal order -> rs386421256 (stale);
                         reversed order -> rs238202 (current)
  chr20:47,829,244 G>C: normal order -> rs73626311 (stale);
                         reversed order -> rs430553 (current)
  (+ 6 more examples, all different depending on order)

CONCLUSION
----------
This is no longer a plausible hypothesis: every ambiguous site, without
exception, changes its answer based on processing order alone -- a
concrete, reproducible demonstration of non-determinism, even though the
literal multi-tool comparison (bcftools/pysam/GATK) remains blocked by the
WSL outage.

STATUS: promoted to Section 5.8 of the manuscript's Results (not left as a
plain limitation), with an honest note on what remains to be done (the real
multi-tool test) once WSL is back.
