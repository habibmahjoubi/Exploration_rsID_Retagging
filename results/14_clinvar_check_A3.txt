ClinVar check on the 369 dbSNP138 (current, stale) pairs — honest negative result
========================================================================================================

CONTEXT: following the critical review, testing whether a fraction of the 369
dbSNP138-stale rsIDs carry a ClinVar pathogenicity classification that a
naive search by the old ID would miss -- would turn the paper from a
"identifier-hygiene paper" into a concrete clinical-safety argument.

METHOD: NCBI E-utilities esearch query (db=clinvar, term=rs{ID}) for
each of the 369 CURRENT rsIDs and each of the 369 corresponding STALE rsIDs
(738 queries, ~0.7s/query with a politeness delay).

METHOD VALIDATION (sanity check):
  rs334  (sickle cell disease, known pathogenic)   -> 10 ClinVar records
  rs6025 (Factor V Leiden, known pathogenic)       ->  3 ClinVar records
  rs202831 (one of our "current" IDs)              ->  0 records
=> The method works correctly (correctly detects known true positives).

RESULT
--------
Total pairs tested                                     : 369
Current ID with >=1 ClinVar record                     : 0
Stale ID with >=1 ClinVar record                        : 0
No pair (neither current nor stale) has ClinVar data    : 369/369

HONEST CONCLUSION
------------------
Clean negative result: NONE of the 369 candidates in this specific panel have a
clinical classification in ClinVar, whether querying the current ID or the
stale ID. This test therefore does NOT allow the paper to be turned into a
clinical-safety argument -- the question of real clinical
consequence remains open, not confirmed.

Plausible explanation (not established): this specific panel (old/low
current rsIDs, filtered on "most recent merge in 2014-2017") is
probably enriched for common, well-established polymorphisms rather than
rare disease-associated variants -- clinically relevant variants
typically have more recent/higher rsIDs or are rare (hence
less likely to have generated duplicate submissions requiring administrative
merging). A panel built specifically from known ClinVar/pathogenic
variants, then checked for a merge history, would be the correct test
to answer the real question -- not done here for lack of time, but identified
as a concrete direction for future work.

STATUS: integrated into the manuscript (Section 6.2 Limitations) as an
honestly-reported negative result, not as "not yet done".
